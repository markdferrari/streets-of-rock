# Visual and delivery procedures — T002

Defined 2026-10-14 before concept/final production. Follow quickstart A–G and contracts; desktop evidence supplements physical acceptance.

## Record format and evidence validity

Every observation records subject, stage (concept/gameplay), source commit, source/asset SHA-256, exact build ID/inventory SHA-256, capture paths and SHA-256, date, actual reviewer, viewport/device/OS/browser, duo, tick/action, settings and result (pending/pass/changes-required). Record actual outcomes and unresolved findings separately. A changed subject/build requires an affected review recheck. Empty screenshots, planned commands, skipped suites and unavailable phones/participants remain pending. Baseline captures are comparison references, never approvals.

## Lifecycle and failed preparation

Omit/corrupt each scene, texture and clip individually: no countdown, duo retained, actionable Retry; repair starts once. Abandon delayed preparation and resolve both stale success/error; neither changes current state, and instances release. Interrupt preparation/countdown, travel, every attack, stun and death through hide/blur/portrait; timing and poses freeze, inputs clear, safe landscape requires explicit Resume and fresh simultaneous movement/action. Repeat canceled touches and denied audio/storage. Muted/no-shake retains warnings; reduced motion removes nonessential motion and pause freezes it.

On iPhone 12/Safari and Pixel 6/Chrome, cache complete release online, close, disable networking, reopen and complete all four rooms/results/retry with intended soundtrack, in browser and installed modes where supported. Force small-cap splitting; cold import/mount resolves every dependency to sole owner without replacement. Ten home/run/retry cycles settle to same instance counts and no progressive retained memory.

## Physical performance and release audits

Record intended track hash, identical Release/Diagnostics content/settings, OS/browser, viewport/render density, duo, raw frame intervals, rolling one-second FPS, longest frames, draws, visible triangles, scenery and character textures separately, total measurable memory. Exclude loading/countdown/paused/hidden/results from active FPS; report transitions/stalls separately. Target 60fps; every active busiest-encounter one-second sample >=30fps on both phones. Require <=100 draws, <=100k visible triangles, density <=1.5, <=64MiB decoded scenery textures with mipmaps, <=30MiB total physical game content and <=16MiB each content file. Account duplicate bytes; only byte-verified stock engine overhead is exempt. Never reduce waves/hide required characters to pass.
